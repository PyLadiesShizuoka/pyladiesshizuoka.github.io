# PyLadies Shizuoka Website

**富士山のふもとで、Pythonとつながる。**

PyLadies Shizuokaの公式Webサイトを管理するリポジトリです。

PyLadies Shizuoka is a Python community for women and gender minorities in Shizuoka, Japan.

- **公式Webサイト：** https://shizuoka.pyladies.com/
- **リポジトリ：** https://github.com/PyLadiesShizuoka/pyladiesshizuoka.github.io

## はじめに

このREADMEは、新しく運営に参加する方が、公式Webサイトの仕組みと更新方法を理解するための手引きです。

現在は、**GitHubのブラウザ画面で編集し、`main` ブランチに直接コミットする**方法で運用しています。初めからすべてを覚える必要はありません。まずは記事の修正など、取り組みやすい作業から始めてみてください。

> **注意：** `main` へのコミットは公開サイトに反映される可能性があります。変更内容を確認してから保存してください。迷った場合は、コミットする前に運営メンバーへ相談しましょう。

## PyLadies Shizuokaについて

PyLadies Shizuokaは、静岡県を中心に活動する、女性およびジェンダーマイノリティを対象としたPythonコミュニティです。

Pythonを学び始めた方から経験者まで、交流や学習を通じてつながれる場を目指しています。

## 1. 更新したい内容から探す

| やりたいこと | 編集する場所 |
| --- | --- |
| トップページの文章を直す | `index.html` |
| ブログ記事を追加・修正する | `_posts/` |
| イベント情報を登録・修正する | `events.json` |
| 画像を追加する | `images/` |
| サイトの色や余白などを変更する | `style.css` |
| ヘッダー・ナビゲーション・フッターを変更する | `_layouts/default.html` |
| ブログ記事の表示形式を変更する | `_layouts/post.html` |
| サイト全体の設定を変更する | `_config.yml` |
| アクセス解析の設定を確認する | `_includes/google-analytics.html` |

共通レイアウトやCSSの変更は複数ページに影響します。最初はブログ記事など、変更範囲が小さい作業から始めることをおすすめします。

## 2. GitHubで編集・公開する手順

### 事前準備

1. GitHubアカウントでログインします。
2. このリポジトリを開き、編集権限があることを確認します。
3. 画面上のブランチ表示が `main` であることを確認します。

### 既存ファイルを編集する

1. リポジトリから対象のファイルを開きます。
2. 鉛筆アイコン（**Edit this file**）をクリックします。
3. 内容を修正します。
4. **Preview** が利用できる場合は、変更内容を確認します。Markdownのプレビューはサイト上の最終表示と完全には一致しない場合があります。
5. **Commit changes** をクリックします。
6. 何を変更したかがわかるコミットメッセージを入力します。
7. **Commit directly to the main branch** を選び、コミットします。

コミットメッセージの例：

- `ブログ記事の誤字を修正`
- `Meetup #3の告知記事を追加`
- `イベント情報を更新`

### 新しいファイルを追加する

対象フォルダを開き、**Add file → Create new file** から作成します。画像などのファイルは **Add file → Upload files** から追加できます。GitHubの画面表示は変更されることがあります。

### 公開を確認する

```text
GitHubで編集
    ↓
mainにコミット
    ↓
GitHub Pagesの公開処理
    ↓
公式サイトで表示確認
```

1. コミットが `main` に反映されたことを確認します。
2. GitHubの **Actions** などで、公開に関係する処理の状況を確認します。
3. https://shizuoka.pyladies.com/ を開き、変更が反映されたことを確認します。

反映まで時間がかかる場合があります。公開処理の詳細はGitHub Pagesの設定によって異なります。

## 3. ブログ記事を追加する

ブログ記事は `_posts/` フォルダにMarkdown形式で保存します。

### ファイル名

`YYYY-MM-DD-記事名.md` の形式にします。

例：`2026-10-13-connpass-thirdevent.md`

### 記事の書き方

```markdown
---
layout: post
title: "イベントを開催しました！"
date: 2026-10-13
---

PyLadies Shizuokaのイベントを開催しました。

## 今回の内容

参加者の皆さんとPythonについて交流しました。

## まとめ

ご参加ありがとうございました。
```

冒頭の `---` で囲まれた部分は、Jekyllが記事を処理するための設定（Front Matter）です。

| 項目 | 意味 |
| --- | --- |
| `layout` | 記事に使用するレイアウト |
| `title` | 記事のタイトル |
| `date` | 記事の日付 |

必要に応じて記事画像も設定できます。既存の記事の記述方法を参考にしてください。記事画像が設定されている場合は、OGP・Xの共有画像にも使用されます。

### よく使うMarkdown

| 書き方 | 用途 |
| --- | --- |
| `## 見出し` | 見出し |
| `**重要**` | 太字 |
| `- 項目` | 箇条書き |
| `[公式サイト](https://shizuoka.pyladies.com/)` | リンク |
| `![画像の説明](/images/example.jpg)` | 画像 |

### 画像を追加する

1. `images/` の適切な場所に画像をアップロードします。
2. 記事内で、実際の保存先に合わせたパスを指定します。

```markdown
![イベントの様子](/images/example.jpg)
```

画像のファイル名は大文字・小文字も含めて一致させてください。画像と記事を別々に追加すると、それぞれコミットが必要になる場合があります。

### 記事公開後の確認

- ブログ一覧に記事が表示されるか
- タイトル・日付・本文が正しいか
- 画像やリンクが正しく表示されるか
- スマートフォンでも読みやすいか

## 4. イベント情報を更新する

イベント情報は `events.json` で管理しています。

| 項目 | 内容 |
| --- | --- |
| `title` | イベント名 |
| `url` | connpassのイベントURL |
| `started_at` | 開始日時 |
| `ended_at` | 終了日時 |
| `place` | 会場 |
| `source` | 情報元 |

日時は日本時間を含む形式で記載します。

```json
"started_at": "2026-09-13T13:00:00+09:00"
```

**既存のイベントと同じ構造で編集してください。** JSONはカンマ、ダブルクォーテーション、括弧の不足などで読み込めなくなることがあります。変更後はサイトのイベント表示を確認します。

## 5. サイトの構成と仕組み

### 使用技術

| 技術 | 役割 |
| --- | --- |
| GitHub Pages | Webサイトの公開 |
| Jekyll / Liquid | ページやブログ記事の生成 |
| HTML / CSS | ページの構成とデザイン |
| JavaScript | メニューの開閉やヘッダー表示など |
| Markdown | ブログ記事の記述 |
| JSON | イベント情報の管理 |
| Google Analytics 4 | アクセス解析 |
| Font Awesome | アイコン表示 |

### 主なフォルダとファイル

```text
├── _includes/       # Google Analyticsの計測コード
├── _layouts/        # 通常ページとブログ記事の共通レイアウト
├── _posts/          # ブログ記事
├── blog/            # ブログ一覧ページ
├── coc/             # Code of Conduct
├── images/          # サイトで使用する画像
├── privacy/         # プライバシーポリシー
├── CNAME            # 独自ドメインの設定
├── README.md        # この手引き
├── _config.yml      # Jekyllとサイト全体の設定
├── events.json      # イベント情報
├── index.html       # トップページ
└── style.css        # サイト全体のスタイル
```

### ページが表示される仕組み

`_layouts/default.html` はサイト全体の共通レイアウトです。ページタイトル、説明、OGP・X用メタ情報、Font Awesome、ファビコン、CSS、ヘッダー、ナビゲーション、本文、フッターなどを管理しています。また、コピーライト年、ヘッダー表示、メニュー開閉のJavaScriptも含まれています。

ブログ記事は次の順序で組み立てられます。

```text
_posts/ の記事
       ↓
_layouts/post.html
       ↓
_layouts/default.html
       ↓
完成したブログページ
```

`_layouts/post.html` は、パンくずリスト、投稿日、記事タイトル、記事画像、本文、前後の記事へのリンク、ブログ一覧へ戻るボタンなどを管理しています。

### OGP・Xの共有画像

記事画像が設定されていない場合は、共通画像 `/images/blog/ogp.png` を使用します。

### Google Analytics

GA4の計測コードは `_includes/google-analytics.html` で管理し、`_layouts/default.html` から読み込んでいます。アクセス解析については `privacy/` にプライバシーポリシーを掲載しています。

## 7. 困ったときは

### コミットしたのに変更が表示されない

- `main` にコミットされているか確認する
- **Actions** にエラーがないか確認する
- 公開処理の完了を待ち、ページを再読み込みする

### ブログ記事が表示されない

- ファイル名が `YYYY-MM-DD-記事名.md` になっているか
- 記事冒頭の `---` と `layout`、`title`、`date` に誤りがないか
- 日付が意図せず未来になっていないか

### 画像が表示されない

- 画像がアップロードされているか
- パスとファイル名（大文字・小文字を含む）が一致しているか

### 間違えてコミットした

GitHubの変更履歴から内容を確認できます。慌てて変更を重ねず、必要に応じて運営メンバーに相談してください。

**個人情報やパスワードなどを誤って公開した場合は、すぐに運営メンバーへ連絡してください。** ファイルを消してもGitの履歴に残る場合があります。
