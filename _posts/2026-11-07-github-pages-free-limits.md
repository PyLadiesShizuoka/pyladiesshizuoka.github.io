PyLadies ShizuokaのWebサイトは、GitHub Pagesを使って公開しています。<br>
普段はGitHub上でファイルを編集し、変更を保存（コミット）することでWebサイトを更新しています。<br>
そんな中、ふと疑問が浮かびました。

**「GitHub Pagesって、何度も更新していたら無料の利用枠を使い切ってしまうのでは？」**

無料で使えるのはありがたいけれど、どこまで無料なのか、実はよく分かっていませんでした。<br>
そこで、GitHubの公式ドキュメントを調べてみました！

## 実は「トークン」を消費すると思っていました {#token}

今回調べるきっかけになったのは、私自身の勘違いでした。

GitHub PagesでWebサイトを更新するたびに、**何かしらの「トークン」を消費している**と思っていたのです。<br>
生成AIのサービスでは、文章の処理量を「トークン」という単位で表すことがあります。<br>
そのイメージから、

- GitHub Pagesも更新するたびに無料枠を消費するのでは？
- ブログを何度も書き直していたら、いつの間にか有料になるのでは？

と考えたり、心配したりしていました。<br>
ところが、調べてみると、GitHub Pagesの更新は**生成AIのようにトークンを消費する仕組みではありません**でした。

代わりに、「ビルド回数」や「通信量」などの制限があることが分かりました。<br>

---
## GitHub Pagesには更新回数の制限がある？ {#build-limit}

GitHubの公式ドキュメントには、次の制限が記載されています。

**1時間あたり10回のビルド（ソフトリミット）**

「ビルド」とは、Webサイトを公開できる状態にするための処理です。

PyLadies Shizuokaでは、GitHub Pagesの「Deploy from a branch」という方法でサイトを公開しています。<br>
GitHub上でブログ記事やCSSなどを修正してコミットすると、通常はJekyllがサイトを生成し、更新されたページが公開されます。<br>
<br>
つまり、**記事の数ではなく、サイトを生成する回数が関係している**のです。<br>
<br><br>
例えば、同じブログ記事でも、<br>
<br>
1. 誤字を修正してコミット<br>
2. 文章を追加してコミット<br>
3.デザインを修正してコミット<br>
<br>
と繰り返せば、その都度ビルドが行われるのが通常です。<br>
ただし、10回というのは「ソフトリミット」です。必ず10回目で停止するという意味ではありません。<br>
また、1日10回までという制限でもありません。<br>

---
## 10回を超えたら有料になるの？ {#pricing}

ここが一番気になっていたところです。<br>
結論からいうと、

**10回を超えたからといって、自動的に有料になるわけではありません。**

GitHub Pagesのビルド回数の制限は、料金の境界ではなく、サービスを安定して提供するための制限です。<br>
制限が適用された場合、ビルドや公開が進まなくなる可能性はありますが、<br>
料金を支払えば単純に回数を増やせるという仕組みではありません。<br>

---
## ほかにも制限はあるの？ {#other-limits}

GitHub Pagesには、更新回数以外にもいくつかの制限があります。

| 項目 | 制限 |
|---|---|
| ビルド回数 | 1時間あたり10回（ソフトリミット） |
| 公開サイトの容量 | 最大1GB |
| 月間通信量 | 100GB（ソフトリミット） |
| デプロイ処理時間 | 10分以内 |

通信量とは、訪問者がWebサイトを閲覧した際などに送受信されるデータ量のことです。<br>
画像が多いサイトやアクセス数の多いサイトでは、通信量も増えます。

## ブログを更新するときに気をつけたいこと

今回調べてみて、普段の更新方法も少し意識するようになりました。<br>
例えば、誤字脱字を3か所見つけた場合、1か所ずつコミットするのではなく、<br>
まとめて修正してからコミットするようにしています。<br><br>
また、CSSを修正したあと、公開ページの表示が変わらないことがありました。<br>
そのときは、ブラウザで Ctrl + F5 を押して再読み込みしたところ、<br>
新しいデザインが表示されました。<br>
これはブラウザに古いCSSが保存されていたことが原因と考えられます。<br>
<br>
**表示が変わらないからといって、すぐに何度もコミットし直す必要はない**ということも学びました。<br>

## PyLadies Shizuokaでは大丈夫？ {#pyladies}

現在、ブログ記事の追加やイベント情報の修正などを必要に応じて行っています。<br>
普段の運用で、1時間に10回もサイトを公開し直すことは多くありません。<br>
そのため、現状の更新頻度であれば、ビルド回数の制限を過度に心配する必要はなさそうです。<br>

今回調べてみて、GitHub Pagesは何度更新しても自動的に有料になるわけではなく、<br>

では、GitHubの有料プランにすると何が変わるのでしょうか？<br>
